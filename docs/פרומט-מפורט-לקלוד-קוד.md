# פרומט מפורט ל‑Claude Code (טקסט רציף ומוסבר)

> פותחים טרמינל בתיקיית הפרויקט, מריצים `claude`, ומדביקים את כל הטקסט שמתחת לקו (כולל בלוקי הקוד).

---

שלום. אני צריך את עזרתך בפרויקט גמר של תלמיד כיתה י' בישראל בתכנות באינטרנט. לפני שתתחיל, חשוב שתבין את ההקשר ואת רוח העבודה: זהו פרויקט בית‑ספרי, והמטרה היא שהוא **פשוט יעבוד ויעמוד בדרישות המורה** — לא יותר מזה. אני מבקש ממך גישה של "ראש קטן": לבצע בדיוק את מה שצריך, בקוד הכי פשוט וקריא שאפשר, ברמה שתלמיד כיתה י' באמת יכול היה לכתוב ולהסביר בעצמו. אל תתחכם, אל תוסיף ספריות, אל תכניס דפוסי תכנות מתקדמים, ואל תשפר דברים שלא ביקשתי. כל שורה שתוסיף צריכה להיות כזו שהתלמיד יוכל לעמוד מולה ולהסביר מה היא עושה, ולכן הוסף ליד הקוד החדש הערות קצרות בעברית, באותו סגנון של ההערות שכבר קיימות בפרויקט.

הפרויקט הוא אתר בנושא אפייה בשם "Ido Bakery & Pastry". הוא כתוב ב‑ASP.NET WebForms עם C# ו‑‎.NET Framework 4.8, כולו בעברית ובכיוון RTL, ומשתמש במסד נתונים מסוג SQL Server LocalDB שנמצא בקובץ `App_Data/Database1.mdf`, עם טבלה בשם `Users`. כבר עברתי על כל הקוד, והוא במצב טוב: יש דף Master משותף, דפי תוכן, טופס הרשמה עם ולידציה של ASP.NET, התחברות מבוססת Session, אזור מנהל מוגן, והשאילתות כבר מאובטחות עם פרמטרים. לכן אני צריך ממך רק **חמישה שינויים קטנים וממוקדים**, ולא לגעת בשום דבר אחר.

השינוי הראשון, והחשוב מכולם, הוא הוספת בדיקת טופס בצד הלקוח באמצעות JavaScript — זו הדרישה היחידה במחוון שעדיין לא מתקיימת בקוד. כרגע הטפסים נשענים רק על ה‑Validators של ASP.NET, והמורה דורש שתהיה גם בדיקה ב‑JavaScript שרצה לפני שהטופס נשלח. אני רוצה את הבדיקה הכי פשוטה שיש: רק לוודא שהשדות החשובים אינם ריקים. אל תוסיף בדיקות נוספות כמו אורך סיסמה, תקינות אימייל או בדיקת שנה — זה מיותר ומסבך. בקובץ `Course/CourseSignup.aspx`, הוסף קודם את התכונה `ClientIDMode="Static"` לשני השדות `txtUserName` ו‑`txtPassword`, כדי שה‑JavaScript יוכל למצוא אותם לפי id פשוט (בלי התוספת ש‑WebForms בדרך כלל מוסיף ל‑id). אחר כך, בכפתור השליחה `btnSubmit`, הוסף את התכונה `OnClientClick="return validateSignup();"` כך שהפונקציה תרוץ בלחיצה ותעצור את השליחה אם משהו חסר. לבסוף, ממש לפני סגירת בלוק ה‑`asp:Content` האחרון בדף, הוסף את הסקריפט הזה:

```html
<script type="text/javascript">
    // בדיקה פשוטה לפני שליחת הטופס: ששם המשתמש והסיסמה אינם ריקים
    function validateSignup() {
        var user = document.getElementById('txtUserName').value.trim();
        var pass = document.getElementById('txtPassword').value.trim();
        if (user === "" || pass === "") {
            alert("יש למלא שם משתמש וסיסמה");
            return false; // עוצר את השליחה
        }
        return true; // הכול תקין, הטופס נשלח
    }
</script>
```

עשה את אותו הדבר בדיוק בדף ההתחברות `Course/Login.aspx`: הוסף `ClientIDMode="Static"` ל‑`txtUserName` ו‑`txtPassword`, הוסף לכפתור `btnLogin` את `OnClientClick="return validateLogin();"`, והוסף סקריפט זהה ברוחו, רק עם שם הפונקציה `validateLogin`. בשני המקרים השאר את ה‑`RequiredFieldValidator` הקיימים בדיוק כפי שהם — הם משלימים את הבדיקה גם בצד השרת.

השינוי השני הוא תיקון באג קטן: כרגע הקובץ `Default.aspx` ריק לגמרי, ולכן מי שנכנס לכתובת הראשית של האתר מקבל דף לבן וזה נראה כאילו האתר שבור. הפתרון הפשוט הוא לגרום ל‑`Default.aspx` להפנות אוטומטית לדף הבית האמיתי, `main.aspx`. החלף את כל תוכן הקובץ כך:

```aspx
<%@ Page Language="C#" AutoEventWireup="true" %>
<script runat="server">
    protected void Page_Load(object sender, EventArgs e)
    {
        // הפניה אוטומטית לדף הבית
        Response.Redirect("~/main.aspx");
    }
</script>
```

השינוי השלישי נועד לוודא שמתקיימת הדרישה שבדפי הנושא תהיה לפחות טבלה אחת. כרגע דפי המתכונים מציגים את רשימת המרכיבים כרשימה רגילה, ואין בהם טבלת HTML אמיתית. בקובץ `Recipes/SimpleMixCakes.aspx`, מצא את רשימת המרכיבים (האלמנט `<ul>` עם פריטי ה‑`<li>`) והחלף אותה בטבלה פשוטה עם שתי עמודות — מרכיב וכמות. השתמש ב‑class בשם `users-grid` שכבר קיים בקובץ ה‑CSS, כך שהטבלה תהיה מעוצבת יפה בלי שתצטרך לכתוב CSS חדש, והוסף `style` ישיר על התגית כדי שהיא לא תהיה רחבה מדי (זה גם מדגים "עיצוב ברמת תגית" שנדרש במחוון):

```html
<table class="users-grid" style="max-width:420px; margin:0 auto;">
    <tr><th>מרכיב</th><th>כמות</th></tr>
    <tr><td>ביצים</td><td>2</td></tr>
    <tr><td>סוכר</td><td>1 כוס</td></tr>
    <tr><td>חלב</td><td>1 כוס</td></tr>
    <tr><td>שמן</td><td>1/2 כוס</td></tr>
    <tr><td>קמח</td><td>1.5 כוס</td></tr>
    <tr><td>אבקת אפייה</td><td>1 שקית</td></tr>
    <tr><td>קקאו</td><td>3 כפות</td></tr>
    <tr><td>מלח</td><td>קורט</td></tr>
</table>
```

השינוי הרביעי הוא הקלה והבהרה של העיצוב, אבל בצורה הכי פשוטה שאפשר — בלי רדיזיין ובלי שינוי מבנה. כל מה שאני רוצה הוא לרכך את הצבעים כדי שהאתר ייראה נקי וקליל יותר. שני קובצי ה‑CSS, `MainStyle.css` ו‑`CourseArea.css`, משתמשים בשמות צבעים מילוליים: `beige` לרקע, ו‑`brown` לכותרות, לכפתורים ולקישורים. בצע החלפה גלובלית (find & replace) של שני השמות האלה בלבד בשני הקבצים: החלף כל `beige` ב‑`#f5f1ea` (גוון בהיר ונקי), וכל `brown` ב‑`#a9745b` (חום רך ובהיר יותר). אל תיגע בשום כלל אחר ב‑CSS ואל תשנה מבנה. אם תרצה שגם טבלת הנרשמים בעמוד הניהול תתאים לצבעים החדשים, אפשר אופציונלית לעדכן גם בקובץ `Admin/Users.aspx` את `BackColor="Brown"` ל‑`#a9745b` ואת `BackColor="Beige"` ל‑`#f5f1ea` — אבל זה לא חובה.

השינוי החמישי הוא מעבר על כל ההערות (comments) הקיימות בפרויקט ותרגומן לעברית. כרגע חלק גדול מההערות בקוד כתובות באנגלית — למשל בקבצים `all.Master.cs`, `App_Start/Helper.cs`, `Course/Login.aspx.cs`, `Course/CourseSignup.aspx.cs`, `Course/CourseArea.aspx.cs`, `Course/Videos.aspx.cs`, `Admin/Users.aspx.cs`, וגם בתוך קובצי ה‑‎.aspx. עבור על כל קבצי הפרויקט (קובצי ‎.cs ו‑‎.aspx) ותרגם כל הערה שכתובה באנגלית להערה קצרה, פשוטה וברורה בעברית שמסבירה מה הקוד עושה, באותו סגנון של ההערות שכבר קיימות בעברית. שים לב — תרגם **רק את ההערות**: אל תשנה שום שורת קוד, שם משתנה, מחרוזת או לוגיקה, ואל תוסיף הערות חדשות שלא היו קיימות (חוץ מההערות שביקשתי בשינויים 1–4). המטרה היא שכל ההערות בפרויקט יהיו בעברית ועקביות, כדי שהתלמיד יוכל להסביר את הקוד בקלות.

חשוב מאוד מה **לא** לעשות: אל תוסיף שאילתות `UPDATE` או `DELETE`, אל תוסיף `Application` state, אל תוסיף ספריות JavaScript או CSS חיצוניות, ואל תכניס Master page נוסף — שום דבר מאלה לא נדרש. אל תשנה את מבנה התיקיות, אל תשנה את סכמת מסד הנתונים ואל תמחק נתונים. שמור על השאילתות הקיימות עם פרמטרים, ואל תחזור לשרשור מחרוזות. מותר לך לגעת בקבצים נוספים **רק** לצורך תרגום ההערות לעברית (שינוי חמישי) — בלי לשנות בהם קוד או לוגיקה.

כשתסיים את חמשת השינויים, בנה את הפרויקט (למשל באמצעות `msbuild baker__id02.sln /t:Build`, או דרך Visual Studio) וודא שאין שגיאות קומפילציה. אחר כך הרץ את האתר ובדוק שהכול עובד: שדף הבית נפתח כשנכנסים לכתובת הראשית; שבטופס ההרשמה, אם משאירים שם משתמש או סיסמה ריקים ולוחצים שליחה, קופצת הודעת ה‑JavaScript והטופס לא נשלח; שהרשמה תקינה נשמרת במסד הנתונים; ושההתחברות עדיין עובדת. לבסוף, כתוב לי סיכום קצר של מה ששינית בכל קובץ. עבוד לפי הסדר, שינוי אחרי שינוי, והראה לי את השינויים תוך כדי.
